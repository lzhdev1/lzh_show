# 第十八轮：图鉴改为“曾经收集”

## 需求

- 图鉴不再要求当前持有物品；只要账号曾经获得过，就显示「已收集」。
- 每个图鉴分类顶部显示该分类的收集完成度。
- 增加「已收集 / 未收集 / 全部」筛选，默认显示全部。
- 已收集记录只增不减，卖出、消耗、放归动物后都不回退。

## 规则

### 收集判定

图鉴收集记录独立于库存和牧场，保存在 `codexCollected`：

| 键 | 收集时机 |
| --- | --- |
| `plant:<cropId>` | 买种子、收获、野外采摘、旧存档库存回填 |
| `mutation:<mutationId>` | 收获带变异的作物、采摘带变异的野菜、旧存档收成回填 |
| `animal:<species>` | 收服野生动物、旧存档牧场回填 |

记录值为 `true`，从不主动删除。旧账号第一次进入时，用当前种子、收成和牧场动物回填一次，保证现有进度直接显示为已收集。

### 合并

- 本地存档 `merge`：旧存档回填结果与已存记录取并集。
- 多端存档合并：`codexCollected` 单独取并集，不参与其他字段的冲突判定。
- 服务端归一化：只接受 `plant:` / `mutation:` / `animal:` 三种前缀，最多 512 条。

## 实现

### 规则唯一事实源

新增 `src/game/codexCollection.ts`：

- `CodexCollection = Record<string, true>`
- `normalizeCodexCollection(raw)`：过滤非法键和值。
- `markCodexCollected(base, keys)`：无新增时返回原对象，避免多余状态写入。
- `codexFromHoldings(seeds, harvest, animals)`：从当前库存与牧场回填。
- `mergeCodexCollections(...records)`：多端取并集。
- `codexPlantKey`、`codexMutationKey`、`codexAnimalKey`。

### 客户端

- `GameData` 增加 `codexCollected`。
- 初始存档用初始萝卜、白菜种子回填。
- `buySeed` 标记作物；`harvestPlot` 标记作物与变异；`foragePatch` 标记采摘作物与变异；`tameWild` 标记动物。
- 本地持久化、`pickSave`、`applyRemoteState`、`checkpoint`、自动保存依赖比较、`saveMerge` 均已接入。
- 远端状态会从种子、收成、牧场动物回填，再与 `remote.codexCollected` 取并集。

### 服务端与数据库

- `FarmSave` 增加 `codexCollected`。
- `initialSave` 用初始种子回填；`normalizeSave` 归一化并与库存/牧场回填结果取并集。
- `loadSave` 读取 `codex_collected`，旧行也能通过库存回填得到记录。
- `saveState` 新增 `includeCodex`：`$24` 为记录 JSON，`$25` 为是否写入；写入后 `save_version=6`，旧客户端不带字段时保留服务端原值。
- state route 用 `"codexCollected" in raw` 决定是否写入。
- `db/schema.sql` 的建表与 ALTER 两处增加 `codex_collected JSONB NOT NULL DEFAULT '{}'::jsonb`。
- 生产 `Dockerfile` 的 farm-rules 复制列表加入 `codexCollection.ts`。
- 生产数据库字段由部署工作流执行 schema 时自动补齐。

### 图鉴面板

- `CodexPanel` 只读 `codexCollected`，不再按 `seeds`、`harvest`、`ranch.animals` 判断卡片状态。
- 卡片右上角统一显示「已收集 / 未收集」，不再显示当前持有数量。
- 页签下方新增完成度条：
  - 常规页显示当前分类，例如「作物收集完成度 11/24 46%」。
  - 有关键词跨类搜索时显示「全部图鉴收集完成度」，例如「33/141 23%」。
  - 筛选只影响列表，不改变完成度数字。
- 搜索框与筛选按钮同一行；窄屏改为搜索框在上、三个筛选按钮整行等分。
- 图鉴遮罩层级设为 70，打开时驾驶、发言、顶部功能按钮不会压住标签与完成度条。
- 筛选结果为空时显示「没有符合条件的条目」。

## 验收

- `pnpm typecheck`、`pnpm build`、主站 `pnpm exec tsc --noEmit` 通过。
- 开发环境测试账号：作物 11/24（46%）、变异 3/27（11%）、动物 1/20（5%），全部图鉴 33/141（23%）。
- 「已收集」筛选：变异页 27 条中只剩 3 条；「未收集」筛选剩 24 条；「全部」恢复 27 条，完成度始终为 3/27。
- 搜索「坐骑」：自动切到跨类模式，进度显示「全部图鉴 33/141」，分组显示动物 20 条，作物与变异各 0 条并给出空提示。
- 曾经收集、后来不持有：把测试账号的菊花脑收成改为 0，再刷新图鉴，卡片仍显示「已收集」；恢复收成至 1。
- 服务端回读：`codex_collected` 33 条，`plant:juhuanao=true`，`save_version=6`。
- 手机 390×844 与桌面 805×775 均实测通过：五类页签完整可见，完成度、搜索、筛选均可用，无横向溢出。
- 主站静态目录已同步；入口 `index-BUfKYxyj.js`、样式 `index-Bl32Igjo.css`、游戏 chunk `loop-DAFa8ujA.js` 均返回 200。

## 说明

- 动物按「曾经收服过」判定，后续放归或卖出仍算已收集，与物品口径一致。
- 图鉴完成度口径：常规页按当前分类，跨类搜索按全部图鉴；用户尚未提出其他口径。
- 旧存档只在第一次载入时回填当前库存，已被卖掉的旧物品无法还原，这部分从本轮上线后开始记录。
