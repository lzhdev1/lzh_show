# 第十七轮：背包

## 需求

顶部的金币展示移除，原位置改成「背包」按钮。打开后是一个四分类背包：

| 分类 | 来源 | 当前状态 |
| --- | --- | --- |
| 装备 | 后续装备道具 | 空分类，显示占位说明 |
| 道具 | 后续消耗道具 | 空分类，显示占位说明 |
| 种子 | `state.seeds` | 数量大于 0 的种子 |
| 杂物 | `state.harvest` / `harvestLots` | 全部收成，含种植收获与野外采摘 |

需求原文写「三种类别」，但列了装备、道具、种子、杂物四项。本轮按四项落地，装备和道具先保留入口与容量，后续接入道具数据时不用再改面板结构。

## 规则

- 每类基础 30 格，同类物品占 1 格，单格最多叠 999；超过 999 自动拆成下一格。
- 背包每升一级，每类 +10 格；最高 Lv15，即每类 30 → 170 格。
- 升级价按当前等级线性递增：当前等级 × 120 金币（Lv1→Lv2 为 120）。
- 每类独立分页。PC 每页 30 格；手机或窄屏每页 10 格。
- 页面底部固定显示资金；升级栏固定在资金栏上方，背包内容单独滚动。

## 实现

### 规则唯一事实源

新增 `src/game/backpack.ts`：

- `BAG_BASE_SLOTS = 30`
- `BAG_SLOT_STEP = 10`
- `BAG_MAX_LEVEL = 15`
- `BAG_STACK_LIMIT = 999`
- `BAG_UPGRADE_UNIT = 120`
- `normalizeBackpackLevel`、`backpackSlots`、`backpackUpgradeCost`
- `bagStackSlots`：`ceil(count / 999)`
- `bagUsedSlots`、`bagAddSlotCost`、`bagAddCheck`

容量判断看「当前已占格 + 本次新增格」是否超过分类容量。已有堆叠继续加数量不占新格，所以满格时仍可把已有物品叠到 999；只有需要新格时才拦截。

### 状态与容量校验

- `GameData.backpackLevel` 默认 1，新增 `upgradeBackpack()`，检查满级与金币后扣费升级。
- `buySeed`：扣金币前检查种子容量，满格提示「种子背包已满（已用/容量 格），先升级背包」。
- `harvestPlot`：收获前检查杂物容量，不够时不收菜、不结算经验。
- `forageActions`：野外采摘前检查杂物容量；如果本次会掉种子，再检查种子容量。容量不足时不消耗菜丛，也不推进采集状态。

### 面板与响应式

新增 `src/ui/BackpackPanel.tsx` 与 `src/ui/backpack.css`：

- 四个分类标签显示各自「已用/容量」。
- 种子按 `CROPS` 顺序拆堆叠；杂物按 `harvestLots` 顺序拆堆叠，变异品保留名称与配色标记。
- 每格显示图标、名称、数量；多堆叠时右上角显示 `1/2`、`2/2`。
- 空分类仍铺满当前页格子，并提示后续开放。
- 分页由 `(pointer: coarse)` 或 `(max-width: 720px)` 判断：满足任一条件每页 10 格，否则 30 格。
- 顶部标题栏、升级栏、资金栏固定；中间格子与分页独立滚动，30 格铺满时也不会把资金挤出可视区。
- 面板遮罩 `.modal-scrim.bag-scrim` 的层级提到 70，驾驶/发言与顶部菜单在背包打开时压到遮罩下方。

`App.tsx` 移除顶部 `coin-pill`，原位置放 `.bag-trigger` 背包按钮（`BagIcon` + 文字，窄屏只留图标）。`backpackOpen` 纳入 `panelOpen`、Esc 关闭、访客态关闭与 HUD 输入阻断。商店、售车行、售货大厅等弹窗内部仍各自显示金币。

### 存档与数据库

- 客户端 `GameData.backpackLevel` 纳入本地持久化、`merge` 默认、`pickSave`、`applyRemoteState`、自动保存依赖比较、`checkpoint` 归一化与 `saveMerge` 原子字段。
- 服务端 `FarmSave` 增加 `backpackLevel`；`normalizeSave` 使用共享 `normalizeBackpackLevel`；`loadSave` 读取 `backpack_level`。
- `saveState` 新增 `includeBackpack` 参数：`$22` 为等级，`$23` 为是否写入字段；写入后 `save_version=5`，旧客户端不带字段时保留服务端原值。
- `blog_front/src/app/api/ttfarm/state/route.ts` 用 `"backpackLevel" in raw` 决定是否写入。
- `db/schema.sql` 在 `CREATE TABLE` 与 `ALTER TABLE` 两处增加 `backpack_level INTEGER NOT NULL DEFAULT 1`。
- 生产 Dockerfile 的 `farm-rules` 复制列表加入 `backpack.ts`。

## 验收

- `pnpm typecheck`、主站 `pnpm exec tsc --noEmit` 通过，`pnpm build` 通过。
- 基线账号 Lv1、种子 27/30、杂物 6/30；打开背包四类均为 30 格，顶部金币消失，原位置显示背包按钮。
- 升到 Lv2：金币 1031 → 911，四类 30 → 40 格，种子页仍 `1/2`，升级价变 240；等待自动保存后调用 `/api/ttfarm/login`，服务端返回 `backpackLevel=2`、`save_version=5`。
- 容量拦截：把种子塞到 30/30 后买南瓜，提示「种子背包已满（30/30 格），先升级背包」，金币和南瓜数量都不变；买已有堆叠的萝卜仍可成功，因为不占新格。
- 999 拆格：注入 1000 份萝卜，种子显示 31/40，第一格 `×999 / 1/2`，第二格 `×1 / 2/2`，第 2 页显示余下 1 格，翻页正常。
- 手机 390×844：每页 10 格，种子 27 格分 3 页，标签 2×2、格子 5 列，升级按钮整行，资金与升级栏可见；第 2、3 页内容正确。
- 装备、道具空分类显示占位说明，分页、升级、资金仍显示。
- 测试数据已恢复到测试前基线（Lv1、金币 1031、种子 27 类、杂物 6 类）。

## 说明

- 升级价 `当前等级 × 120`、Lv1→Lv15 的 30→170 格容量均为本轮实现默认，需求没有给出具体数值。
- 肉品仍留在售货大厅冷柜，不放进杂物，因为肉品有 `species:element` 变异溢价，和作物堆叠规则不同。
- 装备、道具目前没有数据源，先按空分类展示；后续接入时只需补数据源，不必改面板与存档结构。
