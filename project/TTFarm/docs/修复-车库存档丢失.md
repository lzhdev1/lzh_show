# 修复：购车后重新登录车辆消失

## 原因

车库此前只存在于浏览器 local store，账号存档链路没有 `garage`：

- 客户端 `pickSave` 和自动保存监听都没有车库，买车不会触发服务端存档；
- `RemoteState` 里没有车库，登录时 `applyRemoteState` 用服务端存档覆盖游戏状态，本地车库被清空；
- 服务端 `FarmSave` 和 `farm_states` 表也没有车库字段，接口无法保存车辆。

结果是金币扣款会随存档保留，车却只停在当前浏览器里；换设备或清掉本地状态后必须重新购买。

## 修复

- `farm_states` 新增 `garage JSONB NOT NULL DEFAULT '{"cars":[],"activeId":null}'`，旧账号自动得到空车库。
- 服务端存档新增 `garage`：`loadSave` 读出、`normalizeSave` 走共享的 `normalizeGarage` 校验、`saveState` 单独按字段存在与否写库，旧客户端不会误清空车库。
- 生产镜像把 `src/game/garage.ts` 复制到 `farm-rules/`，服务端与客户端使用同一套车型、车漆、车牌和 6 台上限规则。
- 客户端 `RemoteState`、`pickSave`、`applyRemoteState`、自动保存变更对比与冲突合并全部纳入车库；重新登录后恢复车辆列表和当前选中车辆。
- 存档版本随车库写入提升到 4，避免旧版本存档覆盖新字段。

## 验证

- 用测试账号通过接口写入一台「城光」并设为当前车辆，重新登录后仍返回同一台车与 `activeId`。
- 刷新浏览器后打开驾驶面板，显示「我的车辆 1/6 · 城光 京A·T01」，证明服务端存档已灌回客户端车库。
- 在界面上点「驾驶」让未激活的车辆变为当前车辆，1.2 秒自动保存后数据库 `garage.activeId` 已同步更新，证明车库变更能触发客户端自动存档。
- 测试后已恢复测试账号原始存档：金币 1031、车库为空，刷新后驾驶面板显示 0/6。
- `pnpm typecheck`、TTFarm `pnpm build`、主站 `tsc --noEmit` 均通过。
- 前端构建为 `index-C50kJkTL.js` / `index-Cact2lF-.css`。
