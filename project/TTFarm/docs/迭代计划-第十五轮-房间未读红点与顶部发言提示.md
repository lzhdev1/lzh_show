# 第十五轮：房间未读红点与顶部发言提示

基线：第十四轮 `396fb0b`。本轮只补房间消息的到达提示，不改发言与气泡逻辑。

## 1. 未读红点

- `game/chat.ts` 的 `useChat` 新增 `unread`。
- 首次进入房间时拉到的历史消息只建立 `seen` 基线，不补红点，避免刷新后整段历史都算未读。
- 后续轮询里出现、且不是自己发送的新消息，每条把 `unread + 1`。
- 自己发送的消息不计未读；房间切换、退出登录时清零。
- `ChatDock` 的发言按钮右上角显示红点，`aria-label` 变成「发言，N 条未读」；打开面板即调用 `markChatRead()` 清零。
- 面板保持打开时，新消息继续进列表，但不会累积红点。

## 2. 顶部发言提示

- 新消息同时调用 `useGame.notify`，文本格式为 `昵称：内容`。
- `ToastItem` 新增 `chat` 色调；`notify` 增加可选持续时间，聊天提示停留 9 秒。
- `.toast.chat` 白底黑字、左对齐、浅色描边，显示在页面顶部居中位置。

## 3. 验证

- 容器内 `pnpm typecheck` 通过。
- 容器内 `pnpm build` 通过（`index-BHxMW8v5.js`、`index-DcQJI9fo.css`）。
- 向当前房间写入一条他人测试消息后实测：
  - 发言按钮出现右上角红点，`aria-label` 为「发言，1 条未读」；
  - 顶部出现白底黑字提示「xiaosui：收工了，明天见」；
  - 打开面板后红点消失，消息进入房间列表；
  - 测试消息已从 `farm_chat` 清理，未留在正式聊天记录。
